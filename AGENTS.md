This repository is a NocoBase Solution: `nocoproject/` is the application, `nocoproject-cli/` is the daemon and CLI, and the product plans and phase documents are under `nocosolution/NocoProject/`. The NocoSolution repository is included as the `nocosolution/` submodule; its `guidelines/` folder holds the series-wide guidelines, starting with the guideline `nocosolution/guidelines/solution-guideline.md`. NocoSolution is a private, internal repository, so the submodule is optional: code, builds, tests and CI never depend on it. Without access to it, `nocosolution/` stays empty, and every instruction below that refers to it is skipped; work from the English documentation in this repository. The application directory's `.claude/skills/` is generated by `skills sync` and does not belong here.

- At the start of work, run `git pull && { git submodule update --init --remote --merge || true; }`. The submodule step fails without access to NocoSolution; that is expected and not an error.
- Before drafting or revising a plan, changing the skeleton (`trigger`, `run`, `shared/`, or inbox), adding a temporary implementation, or designing cross-Solution integration, read the whole guideline `nocosolution/guidelines/solution-guideline.md` and follow NocoProject's skeleton rules in `nocosolution/NocoProject/docs/skeleton-rules.md`.
- Every other file in `nocosolution/guidelines/` states at its top what it covers and when it applies; before a task, check them and follow the ones that apply to it.
- Do not edit anything in `nocosolution/guidelines/`; in `nocosolution/`, change only `nocosolution/NocoProject/`. When a plan departs from the guideline or needs something it does not cover, mark it in the plan as a departure from guideline section X.Y with the reason, or as a proposal for the guideline; the guideline's maintainer decides whether to update it.
- Never copy text from `nocosolution/` into this repository; write English documentation here instead.
- The NocoProject user manual (for members, project leads and admins) lives in the system-wide knowledge base under the `manual` subtree (pages `manual-*`), not in this repository. A change to what users see or do (screens, flows, permissions, CLI commands) proposes updates to the affected pages with `nocoproject kb propose` and says so in the delivery comment.
- Everything written into this repository is in English: code, comments, file headers and markers, Markdown docs, scripts and their messages, test names, commit messages, branch names, and pull request titles, descriptions and review comments. Chinese appears only as product content: the Chinese locale files (`nocoproject/client/locales/`, `nocoproject/server/locales/`), seed and demo data a Chinese-speaking user sees, test fixtures that exercise Chinese input, and keyword lists that match Chinese text. Name a Chinese UI label in English, with its locale key when that helps (`np.issues.new`), instead of quoting the Chinese. Never edit an applied migration only to translate it. The exception is the `nocosolution/` submodule (the NocoSolution repository): its guideline, product plans and phase documents are written in Chinese.
